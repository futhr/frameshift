# Open Research Questions

## Cross-cutting

- What is the minimum secure Frame Protocol pairing design?
- HTTP, CoAP or another transport after prototype measurements?
- How should capability schemas be versioned?
- What local scheduling semantics belong on-device?
- How should color/profile metadata be represented?
- What mechanical depth is achievable including PSU and connectors?

## Photo Frame

- Select and physically verify a currently available ~27-inch matte QHD raw panel.
- Select the thinnest reliable compatible controller path.
- Can one low-profile PSU feed both display and frame agent?
- Which matte/paper-like surface treatment looks best without destroying contrast?

## Paper Frame

- Revalidate affordable small Spectra/color e-paper development hardware.
- Measure palette rendering and create host-side color transforms.
- Track A2-class panel pricing and availability.
- Investigate monochrome A2 alternatives independently of color.

## Pixel Frame

- Select exact P3 modules and scan mode.
- Validate ESP32-S3 controller compatibility.
- Measure realistic current at indoor art brightness.
- Determine minimum safe PSU size/depth.
- Explore diffuser/canvas/passe-partout treatments.
- Compare deterministic pixel renderers with optional AI reinterpretation.

## macOS

- Prototype Elixir-core packaging and lifecycle.
- Determine the smallest native Swift shell required.
- Validate supported ServiceManagement/launchd background behavior.
- Design local discovery and pairing UX.
